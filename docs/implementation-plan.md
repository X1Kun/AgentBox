## 下一阶段：kind 多节点接入与故障模拟

没有第二台物理宿主机，使用独立 kind 集群模拟两个 Worker，保留现有集群。先验证固定目标调用，再增加路由，避免同时改变接入与调度语义。

1. 为两个 Worker 准备独立状态目录、Unix socket、cgroup 资源子树和普通用户入口，固定运行时依赖与委派配置。
2. 先用受控端口转发接入指定 Worker，验证执行归属、取消、断线和回收，不直接暴露 root daemon。
3. 再加入最小节点配置、健康状态与过期过滤，按归一化在途负载选择 Worker；上报只是提示，最终准入仍由 Worker 原子完成。
4. 覆盖满载、节点停止、入口重连和不确定结果。禁止不确定执行跨节点自动重放；模型不选择任意宿主路径或网络地址。

完成标准：两节点分别执行并清理成功，故障节点不再接新任务，结果带 Worker 归属，同一 MCP/Agent 工具链可调用。kind 共享宿主 CPU、内存和 PSI，只验证分布式功能，不代表物理跨机隔离或性能改善。

## 验证边界与后续工作

- 修改相关代码后先跑单元/race；收尾运行 make check/build。传输、权限或生命周期改动增加一条短真实验证。
- API 可按验证需要使用，保留轮数/超时和结果不确定时停止的语义，不把成本低解释为允许无界循环。
- 正常磁盘 create/delete 超时仍是已知问题，相关场景复现时按阶段日志定位；不作为全部开发前统一的大规模实验门槛。
- 长时间供给、动态 QoS 对照与参数寻优按性能报告需要安排。解释器预加载、动态执行并发、内存压力准入、多租户公平和独立结果查询另行实现。
