# 路线图与阶段验收

更新：2026-10-25｜路线：成熟平台主体＋一个局部扩展。架构以 [DESIGN](../DESIGN.md) 为准。

已决定退役 agentboxd 及其本地执行后端，目标只交付 Kubernetes Job＋Kueue＋containerd/gVisor 链路。旧实现进入功能冻结，仅支持迁移期必要修复、任务收尾和历史复现；不再增加 containerd 直连后端或长期双后端兼容。本轮只更新文档，P0～P4、新接口及实际退役均未完成。

## 1. 状态基线

本地执行、资源控制及 Gateway/MCP 已实现但待退役，证据见[验证指南](validation.md)。新平台、AdmissionCheck、Koordinator 和新版 API/MCP 均未交付。退役决定不代表现有源码已删除或服务已停止。组件所有权以 [DESIGN](../DESIGN.md)为准。

## 2. 总体顺序

| 阶段 | 主要交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0：契约与环境 | 兼容矩阵、资源域、版本锁、任务定义及旧链路清单 | 平台方案与迁移范围明确 |
| P1：成熟平台 | Kubernetes＋Kueue＋containerd/gVisor＋监控＋真实 Job | 不依赖 agentboxd 的执行与回收闭环通过 |
| P2：扩展、接入与退役 | 健康 AdmissionCheck、新 API/MCP、旧链路切换与移除 | 新契约/故障通过，旧服务和活动发布依赖清退 |
| P3：节点控制对照 | 原生 Koordinator 与四组消融 | 兼容与控制权清晰，完成正向或负向结论 |
| P4：单方向深挖 | 准入公平性或节点策略二选一 | 由证据支持，不按功能数量决定 |

不承诺固定天数，不并行堆叠多个新的控制机制。阶段可先交付功能再补正式性能证据，但状态必须分别标明；失败原因不能通过放宽目标掩盖。

## 3. P0：固定兼容与测量契约

交付：

- 只读环境检查与选定的 Kubernetes/containerd/cgroup v2/CNI/gVisor/Kueue/监控/k6 版本矩阵，记录限制和版本来源。
- 一个专用实验 Worker 或明确标注的单机环境；控制面、在线、离线、监控与压测器资源位置图。
- 一个固定在线请求和图片处理任务，输入 manifest、输出校验、线程数、数据/产物介质及保留策略。
- SLO、到达有效性、预热、窗口、静态扫描范围、停止条件和正式/调参场景划分。
- 平台版本锁、配置和实验产物布局的实现约定；只有创建并验证后才增加使用命令。
- 清点 agentboxd、配对 Gateway、旧 API/MCP 调用方、systemd 服务、状态目录与凭据归属；记录可复现旧版本和卸载边界，不立即删除或停服。
- 定义新旧语义差异：提交/查询/取消、断线后继续、Job attempt 与结果验证；明确 Warm、同步低延迟和旧 API 不做等价迁移。

验收：确认所选部署能提供正确权限与资源边界；明确本次没有采用的能力。实际安装在独立环境进行，保留已有集群和宿主服务。Koordinator 版本可先为候选，P3 再完成兼容验证。

## 4. P1：搭建开源平台闭环

按依赖逐步实施：

1. Kubernetes/containerd、在线 Deployment 与可信 Job smoke。
2. Kueue LocalQueue/ClusterQueue/ResourceFlavor；固定配额和资源声明，验证等待、准入、完成、失败及取消。
3. Prometheus/Grafana/exporter、业务指标和 k6；先确认生成器能维持轨迹。
4. gVisor RuntimeClass、受控任务模板、输入/产物与隔离验证。
5. 固定图片任务、产出校验、在线独占容量及多档静态配额对照。

实际任务在 Job Pod 中执行，不调用 agentboxd，不依赖其状态目录、Unix socket 或自管 cgroup。暂不写 AdmissionCheck、不启用 Koordinator，不新建任务队列。

退出条件：

- [ ] 原生组件故障、Job 重试、取消和资源回收可观察，任务资源归属正确。
- [ ] gVisor 路径、无不必要网络/凭据/宿主访问、有界资源和输出通过真实验证。
- [ ] 输入固定且结果可校验；Job 成功与业务成功分别确认。
- [ ] R/B 原始记录完整，在线容量与合理静态运行点已校准。
- [ ] 提供锁定版本的安装、检查、升级回退和限定范围卸载说明。
- [ ] 在未安装或未启动 agentboxd 的独立环境完成 Job 执行与回收，证明平台不隐含依赖旧链路。

可信 runc smoke 只算平台排障步骤，不能替代沙箱验收。普通部署可先证明功能；正式性能若环境不合格，记录限制而不编造成绩。

## 5. P2：健康准入、产品接入与 Daemon 退役

### P2a：AdmissionCheck Controller

复用官方外部 Controller 协议与 controller-runtime。按[扩展设计](admission-check.md)实现样本有效性、滞回、稳定恢复、放行节奏、Pending 等待/Retry、配置状态与决策事件。

必须交付：

- 只管理自身检查项，使用带前置条件的状态更新保护未准入判断。
- 不因健康恶化修改已准入任务为 Retry/Rejected，不抢占任务。
- 重启/leader 切换后恢复状态并防止集中放行。
- 公开预留配额占用、最长等待和 Ready 到实际启动窗口。
- 最小 RBAC、配置校验、指标、Dashboard 与故障排查说明。

验证：确定性策略测试、API 冲突测试、真实 Kueue 故障流程，以及 B/A 对照。与经过静态扫描的配置比较，双方具有相同资源、模板和观测，不能通过减少输入任务美化结果。

退出条件是机制正确且收益/代价可解释，不要求一定性能胜出。若静态配置已足够，可将检查器保留为可选功能。

### P2b：AgentBox 批任务入口

在 P1/P2a 稳定之后实现薄适配：受控模板提交、按 Job 身份查询、显式取消、产物验证与引用。先明确对象身份、输入摘要冲突、重复 attempt、结果保留和鉴权，再定义版本化 API/MCP schema。服务只使用必要 Kubernetes API 权限，不取得宿主 root、containerd/CRI socket 或 cgroup 控制权限。

生命周期复用 Job/Workload，不写第二套全局状态机或数据库队列。新契约提交后断线继续运行；旧同步断线取消仅是迁移前的行为，不作为未来兼容要求。旧工具不静默改义，新平台失败不自动调用 agentboxd。

退出条件：同一任务从新入口到真实 Job 及结果校验完成；取消、重复提交、传输不确定、过期和重试代价可解释。调用方明确使用新版本，旧请求在切换后得到可识别的停用结果，不误投新 Job。没有运行 agentboxd 时完整 API/MCP 流程通过。

<a id="retirement"></a>
### P2c：切换与退役

退役是本阶段明确交付，不延后为长期双后端。P3 的 Koordinator 不作为退役前置；静态预算与 Kueue 已承担基础运行边界。按[运维退役流程](operations.md#retirement)实施：

1. 固定新旧版本、调用契约和切换范围；保存旧源码/构建依据及必要恢复记录，不复制凭据到公开证据。
2. 新平台验收通过后迁移调用方，关闭旧入口新提交，排空或明确取消旧任务；不将旧在途或不确定请求自动转换为 Job。
3. 核对实例、进程、bundle 和 cgroup 回收后，停止并移除旧配对服务；残留清理失败时先保留现场并处理，不能标记已退役。
4. 盘点并清退旧监听、凭据与专属安装资源，保护新平台可能共用的运行时依赖。回退仅作为人工、独立发布操作，不保留请求级自动路由。
5. 从活动构建、发布及部署中移除 agentboxd、专用 runsc CLI 适配、池/本地 QoS 和旧 Unix 转发链路；共用的校验、结果规则与测试经验按需保留。
6. 归档旧运行说明和代码版本，更新默认入口、CI、验证命令及文档，不继续把旧服务作为主产品安装路径。

完成标准：新提交只走目标平台；旧任务无未解释残留；旧服务不再运行或发布；API/MCP 无 Daemon 依赖；隔离、资源边界、失败恢复及新结果语义均有独立证据。迁移验收要求安全与正确性，不要求复现旧 Warm 时延。

## 6. P3：原生 Koordinator 与联动消融

先确认未修改的 CPU Suppress 在锁定版本、cgroup v2、containerd/gVisor 组合上实际生效。确认 BE/LS、batch 扩展资源、Kueue 配额、调度与祖先资源预算一致。

首轮只启用一个明确的 Suppress 策略，记录其他功能关闭状态。目标平台不存在 AgentBox 本地 AIMD 写入者；不自研发现、执行器或 watchdog 替代成熟组件。

使用[验证指南](validation.md#platform)中的 B/A/K/AK 四组。若资源模型改变，需要重建共同基线，不能直接拼接旧轮次。覆盖在途任务长计算、健康恢复、指标故障和实际启动窗口，说明准入与运行中控制的不同贡献。

退出条件：

- [ ] 真实资源值与控制动作核对，目标身份、资源归属和唯一动态写入权成立。
- [ ] 四组有效数据、任务校验与失败成本完整。
- [ ] 至少形成一个可复现的正向或负向结论，公开不确定性。
- [ ] 卸载/回退后无遗留资源配置或任务，作用范围可证明。

若兼容性阻塞，记录证据并停留在 P2 的完整平台，不以自行抢写 cgroup 绕过所有权问题。

## 7. P4：选择一个方向深入

依据正式场景与独立应用的结果选择：

- 准入方向：多租户等待/公平性、资源规格差异、配额占用与健康许可的配合，优先使用 Kueue 已有机制与扩展点。
- 节点方向：原生 Koordinator 出现明确不足时，在其支持边界内研究一个信号或策略，保持其他执行机制一致。

先增加一个未参与调参的应用或轨迹验证迁移，再决定研发；GPU、Checkpoint、复杂拓扑和跨集群不同时展开。没有足够收益可以停止扩展，平台与负向结论仍可交付。

## 8. 旧实现冻结与非目标

agentboxd 已决定退役。迁移期仅修复妨碍安全收尾、复现和切换的必要问题，不继续扩展 Warm、库存、AIMD、本地路由或 containerd 直连适配。已有源码和实验价值通过版本记录、故障经验与平台验收保留，不要求旧组件留在目标链路。

退出近期主线的事项：自研多 Worker 路由、通用 Node Agent、独立批任务队列/配额账本、新 BatchRun CRD、为演示而实现自定义 scheduler、无证据的 PSI 调参、GPU 和 eBPF。

现有代码和四个脚本入口目前仍可用于旧链路复现，并不代表长期支持承诺。平台入口在实现后替代默认路径；旧专用构建和部署按 P2c 清退，不提前创建大量空目录或通用框架。

## 9. 统一交付规则

- 文档区分规划、已实现、已验证和已测收益，使用说明只列实际入口。
- 代码变更先跑相关测试，收尾运行项目规定检查；权限/运行时/生命周期变化补真实短验证。
- 控制器单元测试不能替代 Kueue 集成，kind 不能替代真实节点性能。
- 实验版本、输入、有效开关、原始结果和失败批次全部归档；独立重复、调参/评估分离。
- 不重写历史数据或把新架构宣传为已解决旧故障；不承诺未经验证的性能百分比。
- 发布部署范围必须列出支持组合、容量、风险、故障恢复、结果语义和升级回退，不能仅凭安装成功称生产就绪。
