# 在线健康感知 AdmissionCheck 设计

更新：2026-10-25｜状态：设计，尚未实现。属于[总体设计](../DESIGN.md)的首个局部研发点；实施前置条件是先完成 P1 的 [Kubernetes 批任务平台](../DESIGN.md#platform)，实施与验收进度统一见[路线图](roadmap.md)。

## 1. 扩展边界

使用 Kueue 官方外部 AdmissionCheck Controller：维护本 controllerName 的 AdmissionCheck Active 条件及 Workload 检查项；可独立部署，复用 controller-runtime 的 watch、reconcile、冲突重试与 leader election。不维护队列、配额账本或第二套 Job 生命周期，不直接改 Job suspend。[开发指南](https://kueue.sigs.k8s.io/docs/tasks/dev/develop-acc/)

首版目的仅为控制新增工作。已准入任务的运行中资源交给静态预算或后续 Koordinator；本扩展不因在线高压驱逐任务。

这是独立的 Kueue 扩展，不是 agentboxd 的插件或替代节点 Agent。它不调用旧 Daemon，不拥有容器执行、宿主 cgroup 或本地 Warm 池；agentboxd 的退役不影响其运行依赖。

支持范围先固定一个实验 Worker/健康域、受控 Job 模板、有限资源规格。多租户公平与跨节点健康聚合在独立需求出现后再做。

## 2. 健康信号契约

第一版从现有业务指标与 Prometheus 查询获取有界窗口信号，复用监控平台，不自建节点采集 Agent。指标源与查询由管理员配置，任务不能提交任意查询、URL 或凭据。

每次判定需要：健康域、配置 generation、采集/窗口结束时间、窗口长度、请求样本量、正确且按时完成数、错误/超时计数、数据有效性及原因。业务 SLO 和统计分母在实验前冻结；正式结果仍由独立客户端验证。

- 检查原始样本年龄，而不是仅检查 HTTP 查询成功或查询返回时间。
- 陈旧、空结果、计数重置、不完整序列、查询超时、配置不匹配均按 unknown 处理。
- 有效但零请求的窗口也不自动等于健康；首版要求达到最小样本量，低流量如何放行留作显式策略选择。
- 延迟分位数只在样本量足够时使用；不能把 P99=0 或缺失延迟解释成可以增负载。
- Prometheus 抓取、窗口计算、控制器轮询、Job 启动各有延迟；首版是慢速准入，不承诺毫秒级 SLO 响应。

初期主要使用应用质量判断，PSI 作为诊断指标。若以后比较 PSI 与利用率策略，保持相同执行器和额外 SLO 保护开关，不能让某一组多获得一条反馈通道。

## 3. 内部状态与 Kueue 状态分离

内部状态：

| 状态 | 条件 | 对新许可的影响 |
| --- | --- | --- |
| Unknown | 启动、样本不足/失效、配置切换 | 不发许可，重建窗口 |
| HealthyPending | 有效健康但尚未持续足够时间 | 等待稳定窗口 |
| Healthy | 持续健康且恢复间隔满足 | 按限定节奏发出许可 |
| Protect | 在线质量持续恶化 | 不发许可 |
| Degraded | 配置、权限或依赖故障 | 不发许可，报告原因 |

状态转移按实际经过时间计算，不假设每次 reconcile 间隔相等。阈值、持续时间、最低样本量、最大年龄、放行间隔、最长检查等待和退避都显式配置；默认值须经 P1 预实验确定，不从本地 AIMD 复制。

Kueue 对象状态的使用：

| Workload 阶段 | 检查动作 | 原则 |
| --- | --- | --- |
| 尚未获得配额 | 等待 Kueue 推进 | 不自行抢配额或启动任务 |
| 已预留、检查未通过、健康未稳定 | Pending | 记录预留等待与原因 |
| 已预留、有效持续健康、放行节奏允许 | Ready | 仅更新本控制器负责的检查项 |
| 未准入且检查等待超过配置上限 | Retry，使用锁定版本的退避协议 | 释放长期占用的预留配额后重试 |
| 明确不可支持的任务/策略配置 | 视配置范围报告无效或 Rejected | 不将临时压力判成永久拒绝 |
| 已准入或已经启动 | 不因健康变化撤销许可 | 不写 Retry/Rejected 触发驱逐 |
| 终态/取消 | 观测并收敛本扩展记录 | 不创建补偿任务 |

AdmissionCheck 通常在配额预留后执行。Retry 会释放预留，并可能驱逐已准入工作；Rejected 可停用 Workload。上述规则必须在锁定 Kueue 版本上测试，不能凭状态名称推断语义。[状态协议](https://kueue.sigs.k8s.io/docs/concepts/admission_check/)

Active 表示检查器对相应配置有效可用；在线业务暂时高压通过 Workload Pending 表达，不反复把整个 ClusterQueue 切为无效。

## 4. 许可发放与恢复风暴

每个健康域按配置间隔最多发出有限许可，首版从每次一个开始。单 leader 串行化许可发放；并发 reconcile 不能各自看到同一健康窗口就全部放行。leader election 不提供跨对象原子事务，切换期间的许可上界必须通过故障测试验证。资源规格固定时先用 Kueue 配额限制最大并行任务规模，不自行实现复杂槽位分配。

持久事实使用 Workload 已有检查状态、转换时间和对象身份。重启后重建最近许可情况，并重新积累健康窗口；不能仅恢复内存计数后立即放行整个积压队列。日志保存决策原因、健康样本版本和配置 generation。

每次写入先核对对象 UID、当前检查状态及最新 admission 状态。使用带 resourceVersion 前置条件的更新保护“未准入才能 Retry”的判断；冲突后重新读取判断，不能盲目重放旧 patch。只修改自己拥有的状态项，不覆盖其他 AdmissionCheck。

这保证的是有条件状态更新与许可节奏，不是物理 CPU 预留，也不是任务执行 exactly-once。

## 5. Ready 到启动的异步窗口

健康许可、其他检查完成、Kueue Admitted、Pod 调度与开始工作之间存在时间差。许可发出后健康可能恶化；控制器故障也不会自动清除 Ready。

首版不循环撤销已发许可以追逐瞬时健康，避免与最终准入竞态或意外驱逐。依靠有限配额、恢复间隔和受控任务规格限制风险，分别记录 ready-to-admitted、admitted-to-start 及对应在线质量。

未发许可的工作负载在控制器不可用时继续等待；已发许可仍可能进入运行。不能写成“控制器故障时所有新任务立即停止”。若接管窗口已经破坏目标，先报告边界，再独立讨论受控启动握手；不暗中引入第二套准入。

## 6. 故障与配置行为

| 故障 | 行为与验证重点 |
| --- | --- |
| 指标陈旧/查询失败 | 停止新许可，恢复后重新积累健康窗口 |
| 控制器重启/leader 切换 | 从对象状态重建，避免重复许可或集中放行 |
| API 更新冲突 | 重读重判，不覆盖他人状态、不误驱逐 |
| 权限不足/配置无效 | 暴露配置或依赖故障，不静默 fail-open |
| Workload 被删除并重建 | 按 UID 视为新对象，不套用旧许可 |
| 已准入期间在线恶化 | 不撤销许可，记录在途干扰 |
| Pending 长期占配额 | 在未准入前提下 Retry/退避，公开饥饿和重排成本 |
| 配置 generation 更新 | 未发许可者重建窗口；已发许可保留可追踪的旧决策 |

删除或停用检查策略的流程要明确阻止新提交、等待/处置 Pending、保留在途任务，再修改 ClusterQueue；不能以删除检查项偷偷绕过健康门控。升级回退需要覆盖相同对象上的状态兼容。

## 7. 指标与权限

复用 Kueue 队列/配额指标，补充健康状态、样本年龄、窗口样本量、检查等待、许可次数、Retry、冲突和查询错误、恢复放行速率及控制器 CPU/内存。对象 ID、run ID 和完整决策进入 JSONL/事件，不作为无界 Prometheus label。

Controller 仅具有必要 AdmissionCheck、Workload/status 及配置读取权限；具体集群级/namespace 作用域由 Kueue API 决定并最小化。无宿主 cgroup、CRI socket 或工作负载执行权限；leader election 使用独立受限 Lease 权限。

## 8. 验收

单元测试覆盖真实时间间隔、样本失效、滞回、低样本量、节奏与配置切换；API 集成测试覆盖冲突、重复 reconcile、UID 重建、已有检查项和接近 Admitted 时的 Retry 竞态。

真实 Kueue/Job 验收：不健康保持等待、健康后逐步放行、长等待释放配额、控制器重启恢复、依赖不可用、已运行任务不被本扩展驱逐。原始事件证明没有第二份任务或隐藏重试。

性能验收按[实验协议](validation.md#platform)比较固定配额与扩展，必须同时报告在线及时成功、批任务等待/积压和有效产出。若收益不足，允许保留为可选扩展或停止深挖。
